# Batch concept style review

Applies to batches with at least two reference images. A single image keeps the original concept flow. The current assistant performs visual assessment; Python cannot infer art style from color counts or filenames.

## Assess before generating concepts

Look at every original reference together. Judge the intended game treatment across outline/edge language, stylization, shading and contrast, material rendering, texture density and palette treatment. Describe concrete differences. A green bottle and brown horse can share a style; a pink costume does not automatically make a character an outlier. Different subjects, backgrounds or source media alone are not sufficient evidence. Ask only about substantial differences likely to survive normal pixel-art conversion.

Choose one or two representative assets for the dominant style. Write a concise reusable style profile with rendering instructions, not subject details: e.g. “Grounded fantasy game art; crisp dark outlines, controlled saturation, broad directional shade clusters, readable natural materials, restrained texture.” If no dominant style is clear, explain that and ask which reference should set the baseline before offering to unify toward it. Never choose the first filename as the style simply because it sorts first.

Run `batch` normally. With multiple references and no review, it writes `refs/batch.style.json` and returns `needs-style-review`. This is work for the assistant, not a question the user must answer. Inspect the images, fill the file, and continue automatically when the batch is compatible.

## Review file

One file, `batch.style.json`, beside the anchors, records the assessment and actual user choices:

```json
{
  "profile": "Grounded fantasy game art; crisp dark outlines, broad material shading, controlled saturation.",
  "references": ["potion", "horse"],
  "assets": {
    "potion": {
      "file": "potion.png", "sha256": "<generated by batch>",
      "match": true, "reason": "Compatible material shading and outline treatment.", "choice": null
    },
    "horse": {
      "file": "horse.png", "sha256": "<generated by batch>",
      "match": true, "reason": "Compatible restrained rendering despite different subject colors.", "choice": null
    },
    "character": {
      "file": "character.png", "sha256": "<generated by batch>",
      "match": false, "reason": "Soft pastel anime rendering and decorative highlights differ strongly from the batch.", "choice": null
    }
  }
}
```

- `match: null` means the assistant has not completed the assessment. Fill a real visual reason for each asset; never fabricate an inspection.
- `match: true` means compatible. Leave `choice: null`; there is no user question for that asset.
- `match: false, choice: null` means a detected outlier awaiting the user. The report supplies `needs-style-choice`, a concise `question`, and two `choices`: `original` (“保留原图风格”) / `unify` (“统一画风”). Show the relevant previews and difference reason. If several images have the same issue, ask together and list exactly which images the answer covers.
- Write `original` or `unify` only after the user answers. The assistant's preference is not consent. Reuse recorded choices when the input batch and target style are unchanged.
- `references` names compatible baseline assets in generation order. It contains asset identifiers, not filesystem paths. The first establishes the baseline; later reference assets can use earlier approved concepts. Other compatible assets and unified outliers use those same approved references.
- The generated file names and SHA256 values bind the assessment to the actual images. If input membership or bytes change, Python pauses for review and preserves the old file. Reinspect changed images and the batch composition before updating hashes/membership. Clear affected outlier choices and ask again if the chosen target style/reference set changes; do not silently transfer approval to a different style.

## Generate after the decision

**Keep original:** the outlier receives exactly the existing single-image prompt and no shared-style reference instruction. Its concept file remains `<name>.png`.

**Unify:** the prompt appends the shared style and identifies the style reference assets. The original image supplies identity, pose, silhouette and the anchor's `keep` features. Approved baseline concepts supply rendering style. Preserve identifying colors while adjusting palette treatment; do not recolor everything to the same hue or copy a reference object's subject, costume, anatomy or background. Save the new result as `<name>.unified.png`. An older `<name>.png` cannot satisfy this request.

Generate and inspect the first baseline concept, then subsequent baseline references, then remaining concepts. Attach the original as the content reference and approved baseline concept images as style references. `batch-report.json` records `style_references` as asset IDs and `concept_file` as the exact required filename. These are instructions to the current assistant; Python does not automatically attach images to a generation tool.

Compatible assets receive the shared rendering profile too, keeping the whole set aligned without prompting the user unnecessarily. Inspect the completed concepts together before importing: a shared prompt is guidance, not a mathematical guarantee of matching style. Rework an approved unification if the concept still clashes, then run the existing pixel-grid import/refine/review workflow.

`provider=none` can process compatible and original-style assets locally, but it cannot perform an approved restyle. A unified outlier waits for its `.unified.png` even with `none`. The report still marks resulting grids as visually `pending`, not style-certified.

Keep original and unified concept files distinct. If the reference image, chosen style or baseline concepts change after a unified image was made, regenerate the `.unified.png` before passing it back to `batch`; the script validates input review identity but cannot visually certify or date the external image's style.

## Current scope

This implements the assistant/CLI workflow and machine-readable choices for a future panel. Folder-opening buttons, batch spinners and single-image painting playback are separate UI work. Single-image commands and a batch containing one image keep their previous behavior, even if an unrelated old batch review file is present.
